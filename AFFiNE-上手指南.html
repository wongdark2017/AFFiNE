AFFiNE 项目上手指南

AFFiNE 是一个开源的 Notion + Miro 融合体：文档（Page 模式）与无边界白板（Edgeless 模式）共用同一份数据，主打 local-first、实时协同与 AI Copilot。一套代码支撑 Web、Electron、iOS/Android 与自托管服务端。本指南基于对仓库的深度分析整理，覆盖架构、环境搭建与开发路径。

三

环境搭建（step by step）

前置要求：Node 22.x（.nvmrc = 22.23.0，fnm use 即可）、Yarn 4（corepack enable）、Rust 工具链（rust-toolchain.toml 固定 1.96.0）、Docker。

  1. 安装依赖

    postinstall 会自动跑 workspace codegen（yarn affine init）和 prisma generate。 

    yarn install
  2. 构建 Rust 原生模块

    首次编译较慢；macOS 注意使用系统 strip。

    yarn affine @affine/native build          # 前端用
yarn affine @affine/server-native build   # 后端用
  3. 启动依赖服务

    包含 postgres（pgvector/pgvector:pg16）、redis、mailpit、manticore。 

    cp ./.docker/dev/compose.yml.example ./.docker/dev/compose.yml
cp ./.docker/dev/.env.example ./.docker/dev/.env
docker compose -f ./.docker/dev/compose.yml up -d
  4. 配置后端环境变量

    按需取消注释 DATABASE_URL、REDIS_SERVER_HOST、MAILER_* 等。 

    cp packages/backend/server/.env.example packages/backend/server/.env
  5. 初始化数据库

    等价于 prisma migrate dev + 自定义数据迁移。每次拉新代码有 migration 都要重跑。 

    yarn affine server init
  6. 启动后端

    底层是 nodemon ./src/index.ts，支持热重载。

    yarn affine server dev
  7. 启动前端

    默认 @affine/web，跑在 localhost:8080。 

    yarn dev

  • 测试账号（服务端启动自动创建）：dev@affine.pro / dev、pro@affine.pro / pro、team@affine.pro / team

四

必须理解的四个核心架构概念

概念 1 · 前端 DI

Framework / Scope / Service / Entity / Store

@toeverything/infra（packages/common/infra/src/framework/）提供一个链式注册的 DI 容器。core/src/modules/ 下的 70 个业务模块全部遵循同一范式（以 modules/doc/index.ts 为例）： 

framework
  .scope(WorkspaceScope)                       // 作用域：Workspace → Doc → Editor 层级化
  .service(DocsService, [DocsStore, ...])      // Service：单例业务门面
  .store(DocsStore, [WorkspaceService])        // Store：对接底层数据源（nbstore/yjs）
  .entity(DocRecord, [DocsStore])              // Entity：可多实例的响应式领域对象

React 侧用 <FrameworkRoot> 挂载容器、<FrameworkScope scope={doc.scope}> 注入子作用域、useService(DocsService) 取服务。看懂一个模块，其余 69 个都是复制品。

概念 2 · 状态管理

LiveData

源码在 packages/common/infra/src/livedata/livedata.ts。本质是 RxJS BehaviorSubject + Preact signal 的组合，命名约定以 $ 结尾（如 editor.mode$）。React 里用 useLiveData(xxx$) 订阅，也可直接 .pipe() 套 RxJS 算子。少量原子状态用 jotai。

概念 3 · 数据链路

Yjs → nbstore → 后端

  • 每篇文档是一个子 Y.Doc；block 树存在 Y.Map 里，父子关系用 sys:children 的 id 数组表达（非物理嵌套），文本是 Y.Text。
  • nbstore（packages/common/nbstore）是客户端存储同步引擎，跑在 SharedWorker 里（apps/web/src/app.tsx 创建 worker 并以 NbstoreProvider 注入 DI）。本地持久化：Web 用 IndexedDB、桌面用 SQLite（走 Rust native）；云端同步走 GraphQL + WebSocket。
  • 服务端对应物是 PgWorkspaceDocStorageAdapter（快照 / 增量存 Postgres），文档同步走 Socket.IO 的 SyncGateway（packages/backend/server/src/core/sync/gateway.ts），yjs 更新合并下沉到 Rust（y-octo）。
概念 4 · 编辑器

BlockSuite：schema/model（数据）与 view（Lit 组件）分离

  • 数据：defineBlockSchema({ flavour: 'affine:paragraph', props, ... }) + BlockModel 子类，全部在 blocksuite/affine/model/，与 Yjs 双向响应式绑定。
  • 视图：Lit 组件（如 affine-paragraph），在 blocksuite/affine/blocks/<name>/，通过 BlockViewExtension 绑定 flavour。
  • 运行时：BlockStdScope（framework/std）持有 store + extensions；Page 与 Edgeless 模式共用同一份数据，只是加载不同 extension 集合。
  • 前端接入点：packages/frontend/core/src/blocksuite/ —— manager/view.ts 是 AFFiNE 向编辑器注入自有能力（AI、云、评论、peek-view…）的总装配处；Lit↔React 桥在 block-suite-editor/lit-adaper.tsx。
五

端到端代码追踪：打开一篇文档发生了什么

新人建议沿这条路径通读一遍，走完即可串起 DI、LiveData、nbstore 和 BlockSuite 四个概念。

  1. apps/web/src/index.tsx → app.tsx

    创建 Framework、注册全部模块、连接 nbstore SharedWorker、挂 <FrameworkRoot> + Router。

  2. core/src/desktop/router.tsx

    路由到 workspace 页。

  3. core/src/desktop/pages/workspace/detail-page/detail-page-wrapper.tsx

    DocsService.open(pageId) 拿到 Doc entity，EditorsService.createEditor()，注入 <FrameworkScope>。

  4. detail-page.tsx → core/src/components/page-detail-editor.tsx

    渲染 <BlockSuiteEditor page={editor.doc.blockSuiteDoc}>。

  5. core/src/blocksuite/block-suite-editor/lit-adaper.tsx + editors/page-editor.ts

    usePatchSpecs 组装 extensions → new BlockStdScope({ store, extensions }) → Lit 渲染 block 树。

常用命令速查

cheatsheet

yarn test                                 # vitest 前端单测
yarn workspace @affine/server test        # 后端单测（ava）

yarn workspace @blocksuite/playground dev # 编辑器 playground

七

常见开发任务落点

任务 落点
改 UI / 业务逻辑 packages/frontend/core/src/modules/<模块> + desktop/pages/；通用组件在 packages/frontend/component
加一种新 block ① blocksuite/affine/model/src/blocks/ 定义 schema/model；② 新建 blocksuite/affine/blocks/<name>/（Lit 组件 + view.ts / store.ts extension）；③ 注册进总装配表 blocksuite/affine/all/src/extensions/{view,store}.ts。参考范例：divider（最简）→ paragraph（完整）
patch 编辑器行为 （AFFiNE 侧）packages/frontend/core/src/blocksuite/view-extensions/ + 注册进 manager/view.ts
后端加 API packages/backend/server/src/core/<模块>（resolver / service）+ models/（数据访问层）；可选插件在 src/plugins/（copilot / payment / oauth…）
数据库变更 改 schema.prisma + prisma migrate dev；数据迁移放 src/data/migrations/

九

易踩坑提醒

⚠ 上手前请记住这几条
  • docs 部分内容过时（如 BUILDING.md 写的 Node 20.x），以代码为准：Node 版本看 .nvmrc（22.23.0）。
  • Windows 需开启符号链接支持（开发者模式 + git config --global core.symlinks true）。
  • 每次拉代码后若有新 migration，要重跑 yarn affine server init。
  • @affine/server 单测用 ava 而非 vitest。
  • 改动 GraphQL schema 后前端类型不会自动更新，需重跑 codegen。
本指南基于 AFFiNE 仓库 canary 分支（v0.27.0）的源码分析整理，生成于 2026-07-08。仓库结构与命令可能随版本演进，遇到不一致时以 package.json 与 tools/cli 源码为准。
